En cuatro líneas

  1. Una PRO 6000 alcanza para tener los dos servicios. El cuello no es “no caben”.
  2. Quien se pone lento es siempre el chat de documentos, no el de código.
  3. La decisión es calidad vs. que no se trabe la oficina, no “¿una GPU o dos?”.
  4. Segunda GPU solo si quieren calidad de 32B + pico de 8–15 fluidos + programador al mismo tiempo.

50 personas con el chat abierto no son 50 generando a la vez. El servidor atiende a todos; se gestiona el turno.

Las campañas

Escenario A

Dos modelos grandes

Asistente 32B + programador ~30B en la misma GPU. Calidad alta. Chat de empresa cómodo de a ~5. El equipo de código cabe entero.

Pico 8–15 no

Escenario B

Dos modelos 7B

Asistente 7B + programador 7B. El pico de oficina sí entra (hasta ~20). Calidad no jurada: el 7B no es “el 32B más barato”.

Pico 8–15 sí

Escenario C

Un modelo 32B

Asistente 32B solo (septiembre) y, de julio, coder 32B solo. Sacar al programador no salva 25–50 preguntas distintas a la vez.

25 / 50 distintos: no

Escenario D

7B instruct + coder 32B

Siguiente campaña. Chat chico + programador grande en una GPU. Script listo. Aún no hay números: la máquina está apagada.

Pendiente de medir

Método

Cómo se midió

Prompts del asistente (política de 100 artículos + a01–a50) y del coder (Flask y JWT). Cómo se abrieron N+N conexiones a la vez durante 90 s.

Resumen

Dos modelos de 32B

Caben en una GPU. El chat de documentos se atasca primero. La segunda GPU no es para que quepan: es para que no se trabe el pico.

30 a la vez

Cómo lograr 30 concurrencias

Solo el chat de empresa. Un 32B en una GPU no alcanza. Tres 32B, un 7B, turno de ~5, o empezar con 7B + coder 32B en una máquina.

Cómo leer “se siente bien”

Criterio de las pruebas: cada persona recibe texto a buen ritmo (unas 10 palabras-pieza por segundo o más) y nadie recibe error. Si baja de eso, el chat se siente trabado aunque la máquina no se caiga.

Rapidez vs calidad

No medimos que 7B y 32B tengan la misma calidad. Medimos si la oficina se traba. El 32B se elige porque entiende mejor políticas y escribe código más entero. El 7B se elige para que 8–15 personas no esperen. No son intercambiables.

32B (grande)7B (chico)
Qué ganas Mejor respuesta (matices, excepciones, APIs más completas) Más gente generando a la vez sin que se sienta lento
Qué pierdes Hay que atender el chat de a ~5 si comparte GPU Calidad no jurada; hay que leer respuestas de RRHH y código antes de producción
